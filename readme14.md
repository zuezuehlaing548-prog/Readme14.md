 과제 14: 힙 정렬, 퀵 정렬, 병합 정렬의 성능 비교

1. 실행 환경과 방법

- 파일: `test14.c`
- 컴파일: `gcc -O2 -o test14 test14.c`
- 실행: `./test14`
- 환경: MacBook Air (macOS), 랜덤 seed = 12345
- 데이터: 0 ~ 999999 사이 랜덤 정수 (중복 가능)
- 데이터 크기 n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- 각 n에서 원본 데이터를 한 번 만들고, 모든 알고리즘이 그 원본의 복사본을 사용했습니다.
- 정렬이 끝난 후 오름차순인지 확인했고, 모든 결과가 맞았습니다.

2. 측정 방법

**비교 횟수**
- 데이터 값끼리 비교할 때마다 `less()` 함수로 1씩 증가했습니다.
- 힙 정렬은 힙 구성과 힙 복구 과정의 비교를 모두 포함했습니다.
- 퀵 정렬은 피벗 선택(Median-of-Three)의 비교도 포함했습니다.
- 반복문의 인덱스 검사와 종료 조건 검사는 세지 않았습니다.

**실행시간**
- `clock_gettime(CLOCK_MONOTONIC)`으로 측정했고, 단위는 ms입니다.
- 정렬 시작부터 끝까지만 측정했습니다. 데이터 생성, 배열 복사, 출력은 제외했습니다.
- 모든 알고리즘에 같은 방법을 사용했습니다.

**메모리 사용량 (계산 방법)**
- 프로파일링 도구는 사용하지 않고, 직접 계산했습니다.
- 원본 배열은 공통 비용이라서 제외했습니다.
- 함수 1개의 스택 크기 = 매개변수 + 지역변수 + 반환 주소(8 Byte) + 이전 프레임 포인터(8 Byte)
- 재귀 함수는 `최대 재귀 깊이 x 함수 크기`로 계산했습니다. 최대 재귀 깊이는 프로그램 실행 중에 직접 세었습니다.
- 힙 정렬: `heap_sort` 함수 + `sift_down` 함수 크기 (재귀 없음, 임시 배열 없음)
- 병합 정렬: 임시 배열 (`n x 4 Byte`) + 재귀 호출 스택 + `merge` 함수 크기
- 퀵 정렬: 재귀 호출 스택 + 가장 깊은 곳에서 호출되는 `partition` 함수 크기

 4. 비교·분석

4.1 데이터 크기에 따른 비교 횟수 변화

세 알고리즘 모두 n이 2배가 될 때 비교 횟수가 2배보다 조금 더 많이 늘어났습니다. 예를 들어 병합 정렬은 n=1,000에서 8,682번, n=2,000에서 19,362번으로 약 2.2배가 되었습니다. 이것은 세 알고리즘이 모두 `n log n`에 비례하기 때문입니다.
비교 횟수는 병합 정렬이 가장 적었고, 힙 정렬이 가장 많았습니다. n=20,000에서 힙 정렬(510,603)은 병합 정렬(260,858)의 약 2배였습니다. 이유는 힙 정렬이 값을 내릴 때마다 비교를 2번 하기 때문입니다. 두 자식 중 큰 값을 찾는 비교 1번, 그 자식과 부모를 비교하는 비교 1번입니다. 병합 정렬은 합칠 때 비교를 1번만 합니다. 퀵 정렬은 그 중간이었습니다.

4.2 실행시간 차이

실행시간은 모든 n에서 대체로 퀵 정렬이 가장 빨랐고, 힙 정렬이 가장 느렸습니다. n=20,000에서 힙 정렬은 3.426ms, 병합 정렬은 2.379ms, 퀵 정렬은 약 2.0~2.2ms였습니다.
힙 정렬이 느린 이유는 비교 횟수가 가장 많기 때문입니다. 병합 정렬은 비교는 적지만 임시 배열로 복사하는 시간이 필요해서 퀵 정렬보다 조금 느렸다고 생각합니다. 퀵 정렬은 비교가 힙 정렬보다 적고 복사도 없어서 가장 빨랐습니다.
다만 시간은 0.05~3ms 정도로 매우 짧아서 측정 오차가 있을 수 있습니다. 같은 프로그램을 다시 실행하면 시간이 조금 다르게 나왔습니다. 그래서 시간 차이가 작은 경우(예: 퀵 정렬 세 가지끼리)는 큰 의미가 없다고 생각합니다.

 4.3 메모리 사용량 차이

- **힙 정렬**은 n과 상관없이 76 Byte로 항상 같았습니다. 입력 배열 안에서 정렬하고 재귀 호출도 없기 때문입니다.
- **병합 정렬**은 임시 배열 때문에 n에 비례해서 커졌습니다. n=20,000에서 80,760 Byte였고, 그중 80,000 Byte가 임시 배열(`20,000 x 4`)입니다. 재귀 스택은 깊이 16으로 약 760 Byte밖에 되지 않았습니다.
- **퀵 정렬**은 재귀 스택만 사용해서 800~1,800 Byte 정도였습니다. n이 20배 커져도 메모리는 조금만 늘었습니다. 재귀 깊이가 `log n`에 가깝기 때문입니다.

메모리는 힙 정렬 < 퀵 정렬 < 병합 정렬 순서로 적게 사용했습니다.

4.4 퀵 정렬의 피벗 선택 방법에 따른 차이

- **비교 횟수:** n=20,000에서 Median3(312,005)가 First(364,462)보다 약 14% 적었습니다. 중앙값으로 피벗을 고르면 배열이 더 고르게 나누어지기 때문이라고 생각합니다. 하지만 n=4,000에서는 Median3(56,839)가 가장 많아서, 항상 적은 것은 아니었습니다.
- **실행시간:** 세 방법의 차이가 매우 작았습니다. 측정 오차 안에 있다고 생각해서 어느 방법이 더 빠르다고 말하기 어렵습니다.
- **메모리:** Median3가 가장 적었습니다. n=20,000에서 최대 재귀 깊이가 Median3는 25, First는 34, Random은 37이었습니다. 배열이 고르게 나누어지면 재귀가 덜 깊어지기 때문입니다.

이번 실험은 랜덤 데이터만 사용했습니다. 그래서 First가 나쁜 경우(이미 정렬된 데이터)는 확인하지 못했습니다.

 4.5 시간 복잡도와 공간 복잡도

| 알고리즘 | 시간 (평균) | 시간 (최악) | 공간 |
|---|---|---|---|
| 힙 정렬 | O(n log n) | O(n log n) | O(1) |
| 병합 정렬 | O(n log n) | O(n log n) | O(n) |
| 퀵 정렬 | O(n log n) | O(n²) | 평균 O(log n), 최악 O(n) |

실험 결과도 이 표와 같았습니다. 힙 정렬 메모리는 항상 일정했고(O(1)), 병합 정렬 메모리는 n에 비례했습니다(O(n)). 퀵 정렬 메모리는 아주 조금씩만 늘었습니다(O(log n)). 시간은 세 알고리즘 모두 n log n처럼 늘었습니다.

5. 결론

- 비교 횟수가 가장 적은 것은 병합 정렬이었습니다.
- 가장 빠른 것은 퀵 정렬이었고, 가장 느린 것은 힙 정렬이었습니다.
- 메모리가 가장 적은 것은 힙 정렬이었고, 병합 정렬은 임시 배열 때문에 가장 많았습니다.
- 퀵 정렬의 피벗 방법은 시간 차이가 작았지만, Median3가 메모리(재귀 깊이)에서 조금 유리했습니다.
- 메모리가 부족하면 힙 정렬, 속도가 중요하면 퀵 정렬이 좋다고 생각합니다.
